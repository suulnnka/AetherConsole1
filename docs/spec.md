# AetherConsole 虚拟游戏机 · 规格说明书

| 状态 | 版本 | 日期 |
|---|---|---|
| 送审版(决策已全部拍板,无遗留待定) | v0.5 | 2026-10-24 |

## 1. 定位与目标

AetherConsole 是一台运行在网页上的"梦幻主机"(fantasy console),参照对象为 PICO-8 / TIC-80。

核心形态是**可被其他项目嵌入的运行时库(内核)**:窗口、页面、真实设备输入由宿主项目的"壳"负责;内核只定义虚拟主机本身——显示管线、时序、虚拟输入状态、音频、游戏运行环境。**内核/壳分离**是贯穿本规格的设计原则。

项目分两个阶段:**阶段一**为内核运行时;**阶段二**为创作工具链(精灵/地图编辑器、DAW 音乐编辑器、字体编辑器)。

## 2. 范围与非目标

### 阶段一 · 内核(v1)目标

- 240×180 @ 60fps 渲染管线:三种颜色模式 + 声明式滤镜链
- Canvas2D 与 WebGL 双后端:游戏可用任意内部分辨率渲染(含 3D),内核负责降采样至 240×180
- 精灵 / 地图 / 摄像机辅助层:仿照 GBA 的 tile / 精灵做法(可选,不强制使用)
- 文本绘制 API:随 v1 交付,内置 12px(实际 11px 高)英文字体
- 虚拟输入状态模型:统一虚拟键位 + 手柄/鼠标双视图 API,光标绝对坐标与增量坐标并支持;壳负责真实设备适配、坐标转换,按 60Hz 送入内核
- 8 通道音频:波形合成(参照 PICO-8)+ 2 算子 FM,通道类型自由声明;SFX/BGM 两级序列播放与抢占恢复;单声道,48kHz
- 游戏代码以纯 JS 编写,主线程直接运行
- 私有卡带格式(单卡预期 ≤256KB,暂不设硬上限)
- 存档 API:save / load,约 2KB 存储空间
- 嵌入 API,供宿主项目(如 webos)调用

### 阶段二 · 工具链目标

- **精灵/地图编辑器**:索引色像素绘制(精灵图)+ tile 地图绘制
- **DAW 音乐编辑器**:三级结构——**音色**(波形/FM 参数/FX)、**片段**(音符序列)、**音轨**(编排)
- **字体编辑器**:12px(11px 高 + 1px 间隔)位图字体编辑

三个编辑器产出的均为卡带数据,其数据模型与卡带格式(§9)联动设计。

### 非目标

- 窗口管理、页面布局、宿主 UI —— 壳的职责
- 键盘 / 鼠标 / 手柄的物理采集、改键界面 —— 壳的职责,内核只定义规范映射
- **游戏代码沙箱 / AetherJS 集成** —— 游戏在主线程直接运行,内容视为可信;集成 AetherJS 需大改,暂不做
- **代码编辑器** —— 不做;用户用自己的编辑器写 JS(../webos 已有代码编辑器可复用)
- 移动端与触摸
- TypeScript 官方支持(用户自行转换为 JS)
- 最新版 Chrome 以外的浏览器适配
- 多人输入(仅单人)

## 5. 显示与渲染管线

### 5.1 基本参数

- 逻辑分辨率 240×180,固定 60fps,帧步长固定(1/60s)
- 内部渲染分辨率**不设上限**:游戏可自开 WebGL 等以任意高分辨率渲染,再降采样进 240×180
- 帧时序:**固定步长,不追帧**;游戏须自行保证单帧逻辑 ≤16.6ms,超标表现为掉帧,内核不做补偿

### 5.2 颜色模式(三选一,由卡带声明)

**模式 A · 自选调色板**
程序自选 N 色构成调色板,N ∈ {16, 24, 32}(上限 32);颜色从 65536 色(RGB565)中选取;帧缓冲为索引色;支持运行时更换调色板。

**模式 B · ANSI 256**
固定 ANSI/xterm 256 色调色板,无需任何配置,直接以 8 位索引写像素。

**模式 C · 真彩 + 滤镜**
以任意颜色渲染(2D 或 3D),由滤镜链完成调色板选择(量化)与抖动。适合 3D/渐变类画面。

### 5.3 渲染管线(已定)

```
游戏绘制(Canvas2D / WebGL2,任意内部高分辨率,含 3D)
        ↓ 内核降采样至 240×180(操作在内核中实现)
        ↓ [模式 C] 调色板量化 + 抖动
        ↓ 声明式滤镜链(可与量化联动,顺序可配置)
        → 240×180 最终帧(内核输出)
        ↓ 壳:整数倍缩放、上屏
```

### 5.4 滤镜(声明式,首批清单已定)

量化、Bayer 抖动、误差扩散抖动、扫描线、半色调、像素网格、暗角、CRT 弯曲、色差、颗粒噪声。

滤镜链为声明式组合,后续持续扩充新滤镜不影响内核结构与卡带声明方式。

### 5.5 缩放与上屏(已定)

- **内核只输出 240×180 最终帧**;整数倍缩放与上屏由壳负责;窗口管理不属于内核

### 5.6 WebGL2 与 3D(已定)

- 后端为 **WebGL2**;游戏可自开上下文做 3D / 高分辨率渲染(可用任意三方 3D 库),经内核降采样 + 滤镜链输出
- 内核不提供 3D 封装:游戏自行选择渲染方案,内核只负责"高分辨率画面 → 240×180"这一段

## 6. 图形 API 层

- 基础为**原生 Canvas2D API**,游戏可直接调用绘制
- 内核附加能力(全部可选,不强制):
  - 精灵 / 地图(仿 GBA,规格已定,见下)
  - 摄像机
  - 文本绘制:随 v1 交付
  - 像素级 API `px / rect / line`(模式 A 索引帧缓冲;`line` 为 Bresenham 线段,屏内自动裁剪,已随 PALE CITADEL 切片交付)

### 精灵 / 地图规格(已定)

| 项 | 规格 |
|---|---|
| tile | 8×8,索引色 |
| 精灵尺寸 | **放宽**:8 的倍数任意宽高,自精灵图取块 |
| 精灵图 | 256×256 起,上限可扩展(设计阶段可调) |
| 地图 | 尺寸上限大幅放宽(远超 256×256,可至 4096×4096 tile 量级);实际占用受卡带容量约束,可压缩存储 |
| 地图条目 | 2 字节 = tile 索引 + 水平/垂直翻转(同 GBA) |

### 字体(已定)

- 固件内置默认位图字体:**12px 规格(实际 11px 高 + 1px 间隔,防止黏连),仅英文**
- **自定义字体可随卡带嵌入**(font.bin),运行时替换默认字体
- 字符集扩展随未来固件 / 字体编辑器迭代

## 7. 输入模型

### 7.1 原则

内核只定义并维护**虚拟键位状态 + 光标状态**;键盘、鼠标、手柄的真实采集、键位映射、改键、页面坐标到虚拟坐标的转换,**全部由壳完成**,并以 **60Hz 按帧送入**内核。壳不属于内核。

### 7.2 统一虚拟键位(已定)

| 虚拟键 | 触发源(经壳写入,均可触发) |
|---|---|
| 上 / 下 / 左 / 右 | W/S/A/D、方向键、手柄十字键 |
| 主键 | Z、J、鼠标左键、手柄 A |
| 副键 | X、K、鼠标右键、手柄 B |
| Start | Enter、手柄 Start 键(鼠标不映射) |

手柄无摇杆要求:右摇杆状态仅由鼠标增量驱动。

### 7.3 双查询 API(已定)

同一份虚拟键位状态,提供两个语义视图;游戏按自身玩法选择使用哪份(允许混用):

- **手柄视图**:up / down / left / right、A(=主键)、B(=副键)、Start
- **鼠标视图**:左键(=主键)、右键(=副键)、**光标绝对坐标(240×180 系)+ 移动增量**(两者都支持)

即:按 Z、按 J、点击鼠标左键、按手柄 A,是同一个虚拟键的按下;手柄视图读作"A 按下",鼠标视图读作"鼠标左键按下"。两套操作互不冲突,游戏选定视图设计操作方式。

- 键状态提供"刚按下 / 刚松开"沿检测(实现细节)。

### 7.4 指针锁定增量(已定,随 PALE CITADEL 切片)

指针锁定仍属"鼠标移动",**不新增虚拟键位**:

- 卡带可声明 `lockPointer: true`;壳据此在用户点击画面时请求 `PointerLock`(优先 `unadjustedMovement` 原始输入,免系统鼠标加速,平台拒绝时退普通锁定),并在锁定期间以 `pushInput({ mdx, mdy, lock })` 送入浏览器原始位移增量(不裁剪到 240×180)与锁定状态
- 游戏经 `api.cursor()` 读 `rdx / rdy`(逐逻辑帧结算的原始增量)与 `lock`;典型用法为 FPS 视角(水平 + 俯仰)
- 锁定不可用(环境不支持 / 用户未授权)时,壳在未锁定状态同样送入 `movementX/Y` 位移增量——游戏两种状态手感一致,均为"鼠标动多少视角转多少"的相对转向;仅光标到达窗口边缘后无法继续(点击锁定解除该限制)

## 8. 音频

### 8.1 合成(已定)

- **8 通道**;每通道的合成器类型由卡带**自由声明,不固定分工**:波形合成 或 2 算子 FM;未来会追加其他合成器类型
- **波形合成整体参照 PICO-8**(波形集、细调参数、音符 FX)
- 输出:**单声道,48kHz**;游戏在主线程运行,音频 API 直调、主线程合成

### 8.2 序列播放(已定)

- 播放音频序列时,由游戏**指定通道**
- 两级:**SFX 级**(音效)与 **BGM 级**(背景音乐);SFX 可临时抢占 BGM 通道,**抢占结束后被抢占声部自动恢复**
- 序列组织方式参照 PICO-8;数据三级结构(音色 / 片段 / 音轨)与阶段二 DAW 联动

### 8.3 时钟(已定)

- 音乐推进挂在 **60fps 帧**上,**随暂停而停**

## 9. 游戏运行环境与卡带

- 游戏以纯 JS 编写;TypeScript 用户自行转换
- **主线程直接运行,无沙箱**:不集成 AetherJS(集成需大改,暂不做,未来可议);内容视为可信
- 调试:以浏览器 devtools 为主(见异常行为)
- **卡带:私有格式**;大小上限暂不设,预期单卡 ≤256KB

### 卡带结构(已定草案)

```
cart(私有容器,zip 或自定义二进制,建议扩展名 .acart)
├─ manifest.json   元信息 + 配置:颜色模式 / 调色板 / 滤镜链 / 通道合成器声明
├─ main.js         游戏代码
├─ sprites.bin     精灵图(索引色)
├─ map.bin         地图数据(可压缩)
├─ audio.bin       音色 / 片段 / 音轨 三级数据
└─ font.bin        自定义字体(可选,缺省用固件字体)
```

### 游戏异常行为(已定)

- 内核捕获游戏回调中的异常 → console.error 输出完整调用栈(devtools 调试)
- 内核**停机**:不再调用游戏回调,保持最后画面
- 通过 `on('error')` 上报壳,显示层呈现由壳决定

## 10. 宿主环境与嵌入

- 目标浏览器:最新版 Chrome
- 内核以库形式提供
- 职责划分(已定):
  - 壳 → 内核:按 60Hz 送入虚拟键位 + 光标(绝对 + 增量)
  - 内核 → 壳:输出 240×180 最终帧
  - 壳:整数倍缩放、上屏、窗口

### 嵌入 API(已定草案)

```js
const ac = new AetherConsole();
ac.attach(canvas);      // 壳注入 240×180 canvas,内核绘制最终帧
ac.loadCart(data);      // 装载私有卡带
ac.start(); ac.pause(); ac.stop();
ac.pushInput(state);    // 壳每帧(60Hz)送入键位 + 光标(绝对 + 增量)
ac.on('error', fn);     // 游戏异常上报,壳决定 UI 呈现
```

## 11. 阶段二 · 工具链

三个编辑器均为**独立工具**(不进内核);承载形态(独立网页 / webos 应用)不在本规格范围内约束,由工具链阶段自行决定。产出的数据即为卡带对应区块,数据模型与 §9 卡带结构联动设计。

### 11.1 精灵 / 地图编辑器

- 精灵图:索引色像素级绘制(受当前颜色模式约束)
- 地图:从精灵图中选 tile 铺设,支持翻转(与 §6 规格联动)

### 11.2 DAW 音乐编辑器

三级结构,与内核音频数据一一对应:

| 级 | 编辑内容 |
|---|---|
| 音色 | 波形绘制 / FM 参数 / FX |
| 片段 | 音符序列(音高 / 时值 / 音量 / FX),参照 PICO-8 |
| 音轨 | 片段在 8 通道上的编排(BGM 级);SFX 片段单独触发 |

### 11.3 字体编辑器

- 编辑 12px(11px 高 + 1px 间隔)位图字形
- 产出 font.bin 打入卡带,运行时替换固件默认字体;默认字符集英文,后续扩展
